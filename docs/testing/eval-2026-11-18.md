# Generation-quality eval — 2026-11-18 (run `sonnet5-r1`)

**Scope**: does the shipped pipeline (plan → level → validate/repair → publish → 4 frame nodes) turn real papers and slides into good games? Measures pipeline health, latency, cost and item quality. Does not measure learning outcomes or player fun (usability study). Full generated tables: [eval-2026-11-18-sonnet5-r1-report.md](eval-2026-11-18-sonnet5-r1-report.md). How to rerun: `tools/eval/README.md`.

## Setup

- **Pipeline under test**: the server as shipped (no code path added for the eval). Its `openai-compatible` provider points at `tools/eval/bedrock_proxy.py`, a loopback-only shim to Amazon Bedrock. The server process holds no cloud credentials.
- **Generator**: Claude Sonnet 5 (Bedrock `us.anthropic.claude-sonnet-5`) on all tiers. **Judge**: GPT-5.6 Terra (`us.openai.gpt-5.6-terra`) — a different model family, to avoid self-preference.
- **Corpus** (`tools/eval/corpus.json`): *Attention Is All You Need*, *MapReduce* (OSDI'04), *ResNet* — classic papers; CS231n lecture 1 — slides; CS229 notes (216 pages) — over-limit case; Chinese Wikipedia *间隔重复* — Chinese, text path.
- **Judge rubric**: per unit 1–5 on grounded / unambiguous / important / feedback / mechanic fit / mobile clarity + flags (factual error, answer leak); per frame: boss correctness, faithful lines, no giveaway, structure; per document: coverage of the 6–8 key ideas.

## What the harness found before quality could even be measured (fixed)

| # | Finding | Fix |
|---|---|---|
| F1 | **Every real PDF upload returned 500**: Ktor 3's `formFieldLimit = 4096` also limits file parts; unit tests only used tiny PDFs | limit = request cap, oversize still 413; regression test (commit `d828b77`) |
| F2 | **Every level was truncated** (level output budget 8 000 tokens; real levels need ~10–11 k); long papers overflowed the planner (4 000) | budgets plan 8 k / level 24 k / frame 16 k; default model timeout 120 → 300 s |
| F3 | Job reports `ready` before the default frame exists → an immediate `GET …/frames/case` is 404 | client must treat 404 as "still generating" and POST (idempotent); better: expose frame status in the job (open) |
| ✓ | 216-page PDF rejected with `FILE_TOO_LARGE` and a clear message | as designed |

## Verifying the judge (it is a model too)

Spot checks against the source: **2 confirmed, 1 judge false positive.**
- ✅ MapReduce L4U1 card s5: "the sort ran faster than the best TeraSort result" marked *unsupported*, but the cited chunk says 891 s vs 1 057 s → the generator's answer is wrong, with the evidence in its own citation.
- ✅ Attention, Case boss: the "flawed" claim (41.8 BLEU) is stated by the paper itself in the abstract and Table 2; only the prose says 41.0 → the source is inconsistent, the question has no single right answer.
- ❌ ResNet, Case intro: the judge marked the Summary's "Deeper is always better" as unfaithful — but the suspect is *supposed* to overclaim. The rubric must exempt the suspect's lines. So Case "lines faithful" is under-scored; factual-error counts (19/59 flagged) are an upper bound until a human calibration pass.

## What to change (by expected effect)

| P | Change | Targets | Where |
|---|---|---|---|
| P0 | **Support gate** (ARCHITECTURE §4, not built yet): after validation, a flash-tier check per unit — "does the cited passage support each answer?"; fail → one regeneration, then drop | grounded, factual errors (F: MapReduce s5) | server `compile/` |
| P0 | **Order only when the source states a sequence**: planner may pick `order` only with a quoted passage that lists the steps; validator checks ordinal/sequence evidence | order grounded 2.9 → | prompts + validator |
