二 开发范围与产品流程
建议的第一条纵向切片：选一份获准使用的文本 PDF → 看清解析与生成状态 → 获取经检查的学习包 → 完成一
段游戏化学习 → 作答并读反馈 → 查来源 → 按需追问 → 保存进度与回顾。
内容展示必须可换模板。数据中保留学习目标、讲解节点、问题、选项、解释与来源，不把业务数据直接写死
在视觉组件里。剧情分支若采用，应明确学习目标与汇合点；不能由随机生成破坏知识主线。（PRD 第 4–5 页
：逐句推进，正确与错误路径均继续后续讲解。）
导入 MVP 建议先支持可复制文本的 PDF。大小、页数和语言上限通过真实样本测定；扫描 OCR、复杂公式与
多栏表格不得承诺无损解析。提取不足时提示用户查看原文或换材料。
多来源扩展设独立验收：视频需合法获取字幕或转写及时间戳；其他文件需格式解析；主题检索需可追踪来源。
预取示例可以用于 Demo，但必须标为预取或模拟，不能冒充实时搜索、转写或真实生成。（PRD 第 2 页：上述
扩展本期排除；第 8 页允许明确标注的离线示例。）
视觉由团队共同确定。先评审信息层级、触区、文本长度、正误反馈、加载与失败状态，再实现。多角色、复
杂动画、配音和换装不应阻塞知识闭环。（PRD 第 2 页将这些装饰性扩展列 P2。）
可中断、可恢复、信息可读是移动使用重点。不要鼓励过马路或驾驶时盯屏；“移动途中”优先解释为安全停
留、等候或乘车情境。
首版建议不建会员、支付、多人协同或复杂微服务。是否保留原文查看、重读和错题复习作为必需能力，由团
队在范围评审时确认；不能把本文建议误作已完成开发。

三 模块及技术协作
客户端模块：Kotlin 为课程背景；Compose、ViewModel、Repository 和 Room 是建议技术选型。Android 负责导
入确认、学习 UI、交互状态、来源阅读、本地保存及安装构建。
资料处理模块：识别文件，提取文本与页序号，生成 SourceChunk；保留 document_version 和内容哈希。后续来
源通过适配器转成同一来源记录，不让客户端分别处理每个模型或解析器。
生成模块：带来源的知识点 → 结构化学习包 → 格式检查 → 来源检查 → 语义抽查。模型和提示模板可更换；首
版避免复杂多 Agent 流程。
游戏运行与追问模块：预生成主线在本地推进，实时问题携带当前节点及最小相关上下文；错误、取消、重试
和迟到响应不破坏进度。（PRD 第 5 页规定举手取消回 N，回答后进 N+1；当前模板未定，具体节点恢复规则
待统一。）
验证模块：检查来源存在、来源支持解释、题目答案与反馈一致。模型自检不等于事实正确，格式通过也不等
于证据成立。演示内容要留人工复核记录。
后端边界：一个服务内按模块组织即可。先以 HTTP API＋持久存储完成闭环；长任务需要异步状态，但不强制
立即引入独立队列集群。服务密钥只保留后端，不能进入 APK。
生成状态建议：queued → extracting → generating → validating → ready；可转 failed 或 cancelled。只有保存成功的
ready 包可进入学习；取消后的迟到结果不能覆盖现有记录。
学习状态建议：loading → presenting → awaiting_answer → feedback → next；追问为暂停子状态，来源阅读也不重
置位置。重复提交用幂等键去重。（PRD 第 3、5、7–8 页提供相近边界，可吸收为候选验收要求。）

四 数据与 API 草案
以下均为待技术评审的合约，不代表既有实现。建议核心实体：Document、SourceChunk、GenerationRun、
LearningPackage、LearningNode、Question、LearningSession、Attempt、QuestionTurn 与 Recap。（PRD 第 4–7 页
以句位为中心；本版用节点抽象同时容纳关卡与讲解。）
POST /v1/documents：上传 PDF，返回 document_id、document_version 和解析 job_id。上传前确认资料使用权限
及 AI 处理告知。
POST /v1/generation-jobs：提交 document_id、模板及语言配置；返回 202 与 job_id。带 client_request_id，重复请
求不能重复计费。GET /v1/jobs/{id} 返回状态、错误原因及已完成结果标识。
GET /v1/packages/{id}：返回 content_version、学习目标、节点、题目、反馈、recap 和 source_refs。source_refs 至
少包含 source_id、document_version、page_index、quote；page_index 是 PDF 物理页，印刷页码另存 page_label。
POST /v1/question-turns：携带 package_id、content_version、node_id、问题及 client_request_id；只检索该资料的
必要片段，返回 answer、source_refs、request_id。客户端主动继续后丢弃该次迟到回答。
本地优先建议：已下载学习包包含答题所需答案和解释，以支持断网反馈；本地数据不能被视为不可窥探。课
程学习 Demo 不用于高风险考试。若团队选择服务端判分，则要明确“离线只阅读，在线才能反馈”的限制。
（PRD 第 8 页要求题目离线仍可用；旧计划服务器独占答案方案不再直接沿用。）
学习记录先存本地；服务端同步 Attempt 可作为可选能力，不强制建账户。继续使用既有记录；重读新建会话但
复用内容；重新生成另建 GenerationRun，保留旧版本。（PRD 第 7 页已描述这三种意图，可作为建议实现规则。
）
接口完成条件：前后端共享 schema、合法和错误示例、取消语义、版本规则与超时值；至少一个 mock 与一个
真实后端能通过同一客户端流程。

五 内容质量与数据安全
结构检查：字段类型、节点引用、选项唯一性、答案键存在、状态可达。缺失或不一致的包不进入 ready。
来源检查：引用 ID 来自当前材料，页序有效，引用片段能与提取文本对照。文本匹配只能证明片段存在；“片
段是否支持结论”和“答案是否唯一”仍需语义审核。
演示材料审核：新材料生成后抽查题名、核心概念、结果、至少一道题与解释；对公式、数值和图表做重点人
工核验。不能用早已审核的固定材料代替所有新材料测试。（PRD 第 6、8 页同样强调证据限度；其中竞品错误
案例尚未由我们独立核验。）
追问约束：无依据时明确证据不足并给原文入口，不编造结论；超时、额度不足时允许回到预生成内容。默认
记录来源和状态，不记录完整问题或敏感正文。
资料权限：仅上传有权处理的内容。上传前告知文本将交由外部 AI 处理，提供取消路径。真实使用前确认服务
商条款、保留策略及学校允许范围，不能把整篇论文默认当成可公开数据。
安全边界：文档文本是低信任数据，不能改变系统指令或触发任意工具；后端验证文件类型、大小和归属，限
制解析资源、请求频率和重试。HTTPS 与密钥管理是部署条件。
离线与存储：已有包在生成失败时不被覆盖；存储不足要提示并保留现有记录。原文件、提取文本、学习包与
日志的保存和删除范围需明确。未实现删除和归属控制时应如实标为限制，不宣称已安全上线。
可追溯验收建议：用户能从解释回到对应片段或可靠位置；自动跳页失败时保留可读的页序和原文，不给虚假
的高亮位置。（PRD 第 2、6 页把可靠跳页列 P1；本版优先保证可核对，不先承诺自动定位能力。）

八 仓库部署与成本建议
仓库：建议三至四人团队采用 monorepo，划分 android、backend、contracts、docs；客户端与后端独立构建。
API schema 和样例只维护一个权威版本。若确需不同权限或独立生命周期，再选 polyrepo 并指定契约版本发布
位置。会议尚未决定。
开发环境：先跑本地后端和 mock，再建立共享集成环境。单服务、持久数据库和文件存储足以验证；不要为了
拆模块而直接上多台微服务。共享服务器由团队选择，不默认使用助手运行环境作为长期生产服务器。
部署前确认：平台与区域、学校资料处理限制、HTTPS、密钥注入、存储持久性、休眠、备份、日志和删除策
略。真机必须能稳定访问端点。供应商、实例规格、费用承担者均待确定。
预算公式：月成本＝计算＋数据库＋存储＋流量＋模型输入输出＋可选 OCR／转写／检索。模型费用＝输入

https://doi.org/10.1111/j.1467-9280.2006.01693.x

[2] 回忆与识别并不等价
